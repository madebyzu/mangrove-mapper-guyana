# Contributing to Mangrove Mapper

## Overview

Thank you for your interest in contributing to Mangrove Mapper. This document describes how to propose changes and submit pull requests.

## Getting Started

- Fork the repository and create a branch for your work.
- Keep each branch focused on a single change or feature.
- Sync your branch with the main branch before submitting a pull request.

## Code Style

- Follow PEP 8 naming conventions for variables, functions, and classes.
- Add docstrings for public classes and methods.
- Keep code clear, readable, and well-structured.
- Prefer small, incremental changes.
- Google Earth Engine (GEE) functions use camelCase methods by default. Outside of the GEE api, please use pythonic snake_case

## Testing

- Add or update tests for any new features or bug fixes.
- Run the existing test suite and confirm all tests pass.
- Include any special instructions needed to run tests.

## Pull Requests

When submitting a pull request:

- Limit changes to a single feature.
- Describe what changed and why.
- Verify that your branch passes all checks and tests.

## Review Process

- Respond to review feedback promptly.
- Make follow-up commits to address comments.
- Keep your branch up to date with the target branch.
